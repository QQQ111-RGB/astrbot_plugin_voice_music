# 测试与验收

## 离线回归

Python 3.10+，安装仓库依赖后运行：

```bash
python -m pip install -r requirements.txt
python .selftest/test_selection.py
python .selftest/test_full_voice.py
```

使用最小 AstrBot 桩件与假的播放器、OneBot 接口，不访问音乐服务，不向 QQ 发消息。测试插件包路径由仓库位置确定，不依赖某台服务器。临时完整音频测试文件会在结束后清理。

`test_selection.py` 覆盖 19 组行为：真实 @、裸命令/错误 @/@all、按人和群隔离、普通聊天不改候选及 LLM 标志、越界序号、并发只发送一次、过期、取消、多用户候选、新请求替换旧请求、私聊、语音别名、移除 LLM 工具、慢旧请求、唤醒词、与 @ 混用、当前会话配置、空前缀防误触发及诊断命令授权。

`test_full_voice.py` 使用 330 秒音频，检查文件哈希和时长不变、群聊/私聊目标正确、只产生一条包含文件路径的原生 record 请求、请求小于 1 KiB、旧语音别名走相同路径、非共享目录和无效目标被拒绝、接口异常可报告且不重复发送。它不验证真实 NapCat 转码或 QQ 收件，因此还需要下方人工验收。

旧的 `python .selftest/run_selftest.py` 为联网音源/下载/转码测试，需要可用音乐端点和 ffmpeg；它会下载测试音频。网络或音源不可用也会导致失败，不能替代确定性的离线回归。

## 真实 QQ 验收

测试群中先确认当前唤醒词，下面用 `*` 举例：

| 操作 | 预期 |
|---|---|
| 裸 `点歌 歌名`、裸 `1` | 本插件不搜索、不播放 |
| `*点歌 歌名` 或真实 @ 后 `点歌 歌名` | 显示候选 |
| 候选期间插入普通聊天 | 候选仍属于原发起人 |
| 无自己候选的其他人发 `*1 语音` | 不选择别人的候选 |
| 原发起人在 60 秒内发 `*1 语音` 或 @ 后 `1 语音` | 一次选择只发送一次 |
| 发起用唤醒词，选择用 @，或反过来 | 两种方式等效 |
| 选歌后继续普通聊天 | 不从历史记录再次播放 |
| 选择实际超过 240 秒的完整源音频 | 收到一条语音，能播放到 4 分钟后和尾部 |

2026-10-13 的一次 Docker + AstrBot + NapCat 实机验收中，完整源音频约 11.5 MiB，路径请求约 213 字节，NapCat 转换时长 302.12 秒，用户确认收到单条完整语音并能播放到 4 分钟后。此记录仅代表该已测环境；不保证所有协议端、音源或任意时长都支持。
